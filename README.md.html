Automate Administration - Test Automation Framework

A robust, enterprise-grade Hybrid Test Automation Framework built using Java, Selenium WebDriver, TestNG, and Maven. The framework implements a modular design combining the Page Object Model (POM) pattern with Data-Driven and Keyword-Driven capabilities.

🧩 Architectural Design Pillars

1. Page Object Model (POM)

Each application module has a dedicated Page class inside the Pages package. Page classes contain web element locators, reusable actions, waits, validations, and module-specific workflows.

Test classes remain responsible for test execution, assertions, test flow and reporting. This separation improves code readability, reusability and maintainability.

The current Page Object structure covers: Login, Organization, Organization Approval Details, Users, Permissions, Roles, Groups and Transaction Summary.

2. Base Configuration & Lifecycle

BrowserSetup.java manages global browser initialization, browser selection, window maximization, driver timeouts, reusable scrolling actions and clean browser teardown.

Common browser-level actions are maintained in the Base class so that they can be reused across different Page classes.

3. Data-Driven Configurations

Global execution parameters are externalized from the Java code and maintained inside config.properties. The ConfigReader.java utility reads these values dynamically during test execution.

This allows application URL, browser and other environment configurations to be changed without modifying the test code.

4. Modular Utilities System

  • BrowserSetup.java: Provides reusable browser setup, teardown, waits, scrolling and common browser-level actions.
  • ConfigReader.java: Reads environment-specific configuration values from the properties file.
  • ExtentReportListener.java: Captures test execution information including Info, Pass, Fail, screenshots and execution results in Extent Reports.
  • AccessibilityUtil.java: Performs automated accessibility validation and reports accessibility violations identified during testing.

📦 Application Modules Covered

The framework is structured to support independent automation of individual Administration modules while maintaining reusable common components.

  • Login: Login authentication and related validations.
  • Organization: Organization hierarchy, organization selection and organization-related workflows.
  • Organization Approval: Approval details, approval events and timeline validations.
  • Users: User creation, organization selection, required-field validation and user data verification.
  • Permissions: Permission creation, organization selection, module/permission selection and confirmation.
  • Roles: Role management and related validations.
  • Groups: Group management and related validations.
  • Transaction Summary: Transaction Summary workflows and validations.

🚀 Execution & Setup Instructions

Prerequisites

  • Java Development Kit (JDK) installed
  • Apache Maven installed
  • Chrome / Edge browser installed
  • Browser and WebDriver versions compatible with the execution environment

Local Command Line Execution

Navigate to the project root directory and execute the automation suite using Maven: 

mvn clean test

Targeted Suite Execution via TestNG

The TestNG suite can be used to control and execute the required automation test classes: 

mvn test -DsuiteXmlFile=testng.xml

🔄 Test Execution Flow

  1. Test execution starts through TestNG.
  2. BrowserSetup initializes the configured browser and application URL.
  3. The required Page Object is initialized using PageFactory.
  4. Test methods execute the required application workflow.
  5. Explicit waits are used where required to synchronize browser interactions with the application.
  6. Reusable methods from BrowserSetup are called from Page classes when common browser actions such as scrolling are required.
  7. Assertions validate the expected application behavior.
  8. ExtentReportListener records Info, Pass, Fail and execution details.
  9. Screenshots and execution results are captured for failed scenarios where configured.
  10. Browser teardown is performed after test execution.

📈 Post-Execution Reporting

Upon test execution completion, reporting and diagnostic information is generated within the project workspace.

  • Extent HTML Reports: Provides graphical execution results including Info, Pass, Fail and test execution details.
  • TestNG Reports: Provides standard TestNG execution results.
  • Screenshots: Captured during failed test execution where configured.
  • Console Logs: Displays execution information, pass/fail status and diagnostic messages during runtime.

♿ Accessibility Testing

Accessibility validation is supported through AccessibilityUtil.java. The utility performs automated accessibility checks against application pages and identifies accessibility violations.

Accessibility results are integrated with the test execution flow and can be reviewed along with the generated Extent Report.

♻️ Reusability & Maintainability

  • Common browser operations are maintained in BrowserSetup.java.
  • Page-specific locators and actions are maintained inside individual Page classes.
  • Test classes contain test execution and validation logic instead of directly handling page locators.
  • Configuration values are maintained externally in config.properties.
  • Common methods can be reused across multiple modules, reducing duplicate automation code.
  • Changes to page locators can generally be handled inside the corresponding Page class without changing the complete test flow.
